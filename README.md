# DocCheck

Веб-приложение для сверки КФЗ с первичными документами. Стартовый экран — «Новая проверка». Результат начинается с заключения со счётчиками. Ниже расположена таблица показателей и дополнительные проверки. Строки раскрываются на месте, документ открывается в боковой панели с подсветкой суммы.

## Возможности

- Выбор одного КФЗ и нескольких первичных документов на одном экране; локальная демо-очередь и готовый пример из приложенного набора.
- Сводка результатов, пояснения в таблице, переход к первичному документу и заключение.
- Сверка таблицы с документом, реквизиты над документом, фильтры аннотаций и масштабирование.
- Единый интерфейс бухгалтера с пояснениями и рекомендациями по результатам правил.

## Локальный запуск

Требуются Node.js 22 и npm 10.

```sh
git clone https://github.com/ananakimov/project-placeholder.git
cd project-placeholder
npm ci
npm run dev
```

## Проверки и сборка

```sh
npm test
npx tsc --noEmit
npm run build
```

Сборка использует TanStack Start / Nitro. Скрипт `scripts/prepare-sites.mjs` также подготавливает каталоги `dist/client` и `dist/server` для Sites.

## GitHub Pages

Сайт: [ananakimov.github.io/project-placeholder](https://ananakimov.github.io/project-placeholder/).

Изменения в `main` автоматически проходят сборку и тесты, затем публикуются через `.github/workflows/deploy-pages.yml`. В настройках репозитория Pages должен использовать источник **GitHub Actions**.

```sh
npm run build:pages
```

Эта команда создаёт статическую версию в `dist/client`. По умолчанию базовый путь — `/project-placeholder/`; переменная `PAGES_BASE_PATH` позволяет изменить его. Внутренние страницы и обновление страницы поддерживаются без серверного процесса.

## Текущее состояние

DocCheck демонстрирует сценарий главного бухгалтера: выбор комплекта, очередь, результат сверки и просмотр доказательств. Меню компактное на десктопе. Список проверок показывает новые задания сверху, поддерживает поиск и фильтры по финансовому результату. Фильтры «Есть расхождения» и «Неполные данные» могут включать одну проверку одновременно.

«Новая проверка» принимает один КФЗ и первичные документы. Очередь восстанавливает этап и прогресс по времени запуска. «Загрузить пример» запускает анимированную демонстрацию на встроенном комплекте и добавляет отдельный результат в историю. Для выбранных пользователем файлов сохраняются только метаданные добавления, а для сверки нужен сервер.

В результате вверху показано заключение со счётчиками по статусам, ниже — таблица из шести колонок. При раскрытии показателя виден список его источников, а подсветка строки соответствует документу в правой панели. Документ открывается справа с подсветкой подтверждения, на телефоне область просмотра появляется над таблицей. Первое открытие глазиком показывает исходный КФЗ, а переключатель позволяет открыть каждый документ комплекта. Повторное открытие восстанавливает выбранный источник, страницу и масштаб. Вкладка «Документы» различает прочитанные, исключённые и файлы с ошибкой чтения. Ниже показаны дополнительные проверки и недостаточные подтверждения.

Пример КФЗ №3/7 использует комплект `fixtures/synthetic-2027/input` по договору SYN-27/04-018 за январь–май 2027 года. Просмотрщик отображает подготовленные страницы PDF, PNG, DOCX и XLSX. Хеши, размеры и координаты описаны в `src/data/sample-document-pages.json`, страницы находятся в `src/assets/sample-documents`. Контрольный JSON `fixtures/synthetic-2027/reference/expected.json` используется тестами.

Манифест `src/data/sample-document-pages.json` содержит SHA-256 оригиналов, размеры страниц и bbox. Его и изображения пересоздаёт `scripts/render-sample-documents.py --office-pdfs <каталог PDF из DOCX/XLSX>` (Python: Pillow, pdfplumber, pypdfium2). Для XLSX используется экспорт LibreOffice `pdf:calc_pdf_Export:{"SinglePageSheets":{"type":"boolean","value":"true"}}`, для DOCX — обычный экспорт PDF. Исходники при этом не изменяются. Конвертация выполняется заранее, не в браузере или Pages; модель и сервер не нужны.

В демо можно принять конкретную версию, открыть её в архиве, изменить состав документов и запустить повторную проверку. История версий сохраняется в браузере. Требования к серверной обработке и кешу OCR описаны в [продуктовых решениях](docs/product-decisions.md). Синхронизация UX направлена из этого репозитория в интегрированный DocCheck через NRT-107.

## Разработка

Стек: React 19, TypeScript, TanStack Start / Router, Tailwind CSS 4, Radix UI, Vite и Vitest.

Репозиторий связан с [проектом Lovable](https://lovable.dev/projects/9228d300-4935-4d89-928b-ec3268542aca). Изменения в `main` синхронизируются с редактором Lovable.
