# DocCheck

Веб-приложение для сверки КФЗ с первичными документами. Стартовый экран — «Новая проверка». Результат начинается с заключения и списка проблем; ниже расположена таблица показателей. Строки раскрываются на месте, документ открывается в боковой панели с подсветкой суммы.

## Возможности

- Выбор одного КФЗ и нескольких первичных документов на одном экране; готовый пример из приложенного набора.
- Заключение, счётчики, покрытие по сумме и переход из проблемы к раскрытой строке.
- Сверка таблицы с документом, реквизиты над документом, фильтры аннотаций и масштабирование.
- Переход между расхождениями, отметки проверки и комментарии.
- Подпись заключения и скачивание результата в PDF (через печать браузера) или JSON.
- Единый интерфейс бухгалтера с пояснениями и рекомендациями по результатам правил.

## Локальный запуск

Требуются Node.js 22 и npm 10.

```sh
git clone https://github.com/ananakimov/project-placeholder.git
cd project-placeholder
npm ci
npm run dev
```

## Проверки и сборка

```sh
npm test
npx tsc --noEmit
npm run build
```

Сборка использует TanStack Start / Nitro. Скрипт `scripts/prepare-sites.mjs` также подготавливает каталоги `dist/client` и `dist/server` для Sites.

## GitHub Pages

Сайт: [ananakimov.github.io/project-placeholder](https://ananakimov.github.io/project-placeholder/).

Изменения в `main` автоматически проходят сборку и тесты, затем публикуются через `.github/workflows/deploy-pages.yml`. В настройках репозитория Pages должен использовать источник **GitHub Actions**.

```sh
npm run build:pages
```

Эта команда создаёт статическую версию в `dist/client`. По умолчанию базовый путь — `/project-placeholder/`; переменная `PAGES_BASE_PATH` позволяет изменить его. Внутренние страницы и обновление страницы поддерживаются без серверного процесса.

## Текущее состояние

Это интерактивный прототип с заранее подготовленными данными, без бэкенда. «Новая проверка» содержит два компактных блока: один КФЗ и список первичных документов. Запуск доступен после заполнения обоих. «Загрузить пример» заполняет их и открывает результат `g`. Выбранные файлы хранятся в памяти сессии и не обрабатываются; ручная загрузка также открывает фиксированный пример. На узком экране блоки располагаются друг под другом.

Пример `g` соответствует приложенному синтетическому набору: **КФЗ № 3/7, строка «3 этап, 2027 г.», договор SYN-27/04-018, январь–май 2027**. Все 23 исходных файла сохранены в `fixtures/synthetic-2027/input`, имена, размеры и SHA-256 — в `src/data/sample-files.ts`. Контрольный JSON из архива лежит отдельно в `fixtures/synthetic-2027/reference/expected.json` и используется только тестами, не кодом приложения. Значения сверены с КФЗ и первичными документами; это подготовленный снимок, не результат запуска OCR. Пример из NRT-86 относится к другому договору и не подменяет этот набор; в NRT-89 дополнительных значений не найдено.

Порядок показателей повторяет колонки КФЗ; детализация «в том числе» вложена в статьи 0200 и 0300 и не увеличивает покрытие. В наборе 2 подтверждённых показателя, 2 расхождения и 2 непроверенных; итог служебный и в счётчики не входит. По 0300 разница **+14 800,00 ₽**, по 0800 **−25 000,00 ₽** (КФЗ минус документы). Материальные затраты **128 500,00 ₽** не подтверждены, поэтому у итога **7 818 300,00 ₽** нет полной суммы по документам и разницы (`null`). Общий итог этапа **8 918 300,00 ₽** не смешивается со строкой 2027 года. Дубль, июньский акт и акт по другому договору исключены.

В «Источнике» примера `g` показаны страницы всех 23 исходных файлов: PDF и PNG — исходное содержимое, DOCX — страницы после конвертации LibreOffice, XLSX — весь лист без разбиения колонок. Страницы сохранены как lossless WebP в `src/assets/sample-documents`; они не собираются из `doc.fields`. Координаты подсветки привязаны к этим страницам: для текстовых файлов — по текстовому слою, для сканов — по проверенным вручную областям. Сохраняются переходы между документами, масштаб, переход к сумме и чекбоксы Даты/Суммы/Номера/Договоры. У КФЗ подсвечивается итог строки 2027 года; отсутствующая дата не размечается. Для старых примеров `a`–`c`, у которых нет исходных файлов, сохранён прежний просмотрщик. Произвольные загрузки по-прежнему не обрабатываются. Имя и роль внизу боковой панели убраны; подпись заключения сохранена.

Манифест `src/data/sample-document-pages.json` содержит SHA-256 оригиналов, размеры страниц и bbox. Его и изображения пересоздаёт `scripts/render-sample-documents.py --office-pdfs <каталог PDF из DOCX/XLSX>` (Python: Pillow, pdfplumber, pypdfium2). Для XLSX используется экспорт LibreOffice `pdf:calc_pdf_Export:{"SinglePageSheets":{"type":"boolean","value":"true"}}`, для DOCX — обычный экспорт PDF. Исходники при этом не изменяются. Конвертация выполняется заранее, не в браузере или Pages; модель и сервер не нужны.

Пользователь — главный бухгалтер и его заместители. Роль одна: действия бухгалтера доступны сразу, без переключателя ролей и серверной авторизации. Можно отмечать просмотр, оставлять комментарии и подписывать заключение после просмотра всех проблемных строк. Подпись содержит должность, имя и время, сохраняется в памяти сессии; журнала действий нет. Маршрут `/checks/$id/exceptions` и варианты ручных правок сохранены, но вкладка убрана из основной навигации до решения по вариантам.

В шапке проверки остаются две вкладки: «Результат» и «Документы»; показан вывод вместо состояния проверки. Результат объединяет заключение, три счётчика, покрытие, список проблем и таблицу на всю ширину. Клик по проблеме сбрасывает фильтры, прокручивает к строке и раскрывает её. Строки доступны с клавиатуры (Enter/Space, `aria-expanded`). В раскрытой строке показаны документы и слагаемые суммы; клик по документу открывает «Источник» с bbox-подсветкой. Закрытие панели сохраняет раскрытие и возвращает фокус к документу.

Для расхождений и непроверенных строк показаны результат правила, возможные причины и рекомендация из подготовленных данных. Языковая модель не используется. Подтверждённые строки не содержат блока объяснения. В боковой панели сохранены вкладки «Источник», «Объяснение и рекомендация» и «Правило». Экспорт доступен одной кнопкой «Скачать результат» в заключении: PDF и JSON. Функция `checkToCsv` оставлена в библиотеке, но в интерфейсе не используется.

В панели источника заголовок и возврат к таблице находятся в одной строке, суммы показаны компактно. Реквизиты объединены со счётчиком документов, фильтры подсветки — с настройками страницы и масштаба. На узком экране настройки переносятся, сохраняя доступ ко всем кнопкам. Оставшуюся высоту занимает прокручиваемый документ; переходы между файлами, bbox-подсветка и возврат к раскрытой строке сохранены.

Кнопка «На весь экран» разворачивает источник на всё окно, «Свернуть» возвращает его в боковую панель. Просмотрщик при переключении размера не пересоздаётся: выбранный документ, страница, масштаб и настройки подсветки сохраняются. Переходы между документами и к сумме работают в обоих режимах; закрытие возвращает к раскрытой строке таблицы.

Во вкладке «Документы» три фильтра со счётчиками: «Все», «Прочитано» и «Ошибочные». В ошибочные входят дубликаты, документы вне периода или по другому договору и непрочитанные файлы. Колонка «Состояние» показывает конкретную причину. Расхождение суммы показателя само по себе не делает прочитанный файл ошибочным.

## Разработка

Стек: React 19, TypeScript, TanStack Start / Router, Tailwind CSS 4, Radix UI, Vite и Vitest.

Репозиторий связан с [проектом Lovable](https://lovable.dev/projects/9228d300-4935-4d89-928b-ec3268542aca). Изменения в `main` синхронизируются с редактором Lovable.
