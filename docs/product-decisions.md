# Продуктовые решения DocCheck

DocCheck помогает главному бухгалтеру и его заместителям проверить КФЗ по первичным документам, понять происхождение суммы и открыть подтверждающий фрагмент. Ветка `main` репозитория `ananakimov/project-placeholder` задаёт дизайн и пользовательские сценарии.

## Реализовано в UX-прототипе

| Сценарий | Поведение |
| --- | --- |
| Навигация | «Новая проверка», «Проверки» и «Архив проверок». На широком экране меню свёрнуто до значков. Наведение и клавиатурный фокус раскрывают его поверх рабочей области. На сенсорном экране доступно нажатие на логотип. |
| Список проверок | Колонки «Проверка», «Результат», «Покрытие по сумме», «Документы», «Дата». Строка открывается целиком и сохраняет ссылку для перехода с клавиатуры. Новые задания выше, при совпадении времени порядок задаёт ID. У готовых примеров есть календарная дата. При наличии извлечённого номера отображается «КФЗ №…», а без подтверждённого номера новый запуск называется «Проверка КФЗ» с коротким идентификатором. |
| Фильтры | «Все» показывает непринятые результаты, запуски примеров и версии в обработке. Принятые версии доступны в архиве. Задания без серверной сверки остаются в очереди загрузок. «Есть расхождения» и «Неполные данные» могут включать один результат одновременно. «Неполные данные» также учитывают добавленные файлы без извлечённых полей. «Без расхождений» требует подтверждения всех применимых показателей и доступных данных о комплекте. Состояние задания не даёт финансового статуса. Демонстрационное происхождение данных указано в очереди запусков. |
| Несколько комплектов | В форме один КФЗ и список первичных документов. После добавления комплекта форма очищается. «Очередь проверок» показывает время, число файлов, этап и прогресс. При запуске примера встроенный набор проходит демонстрационные стадии. Для него открывается отдельный результат с исходниками примера. При выборе пользовательских файлов сохраняются только метаданные работы формы, распознавание и финансовый результат недоступны. Состояния восстанавливаются по времени запуска. |
| Результат | Заключение о достоверности вверху содержит подробности и выделенные суммы открытой версии. В одной карточке покрытия — полосы по строкам и по сумме, ниже суммы и доли по статусам. Рублёвые значения берутся из результата. Неденежные и служебные показатели не увеличивают рублёвое покрытие. |
| Таблица и расчёт | Шесть колонок «Показатель КФЗ», «В КФЗ», «Ожидаемо», «Разница Δ», «Статус», «Пояснение». Единица отображается у значения. Полный текст статуса доступен по наведению и фокусу. В раскрытии видны документы и слагаемые при известном основании, исключения, значения и частичные подтверждения. Неизвестное значение отображается прочерком. Возможные причины вынесены в раскрываемый список. |
| Правая панель | Клик по документу открывает просмотрщик и записанный фрагмент. На широком экране таблица и источник доступны одновременно. Глазик закреплён в правой боковой панели. При первом открытии он показывает исходный КФЗ. Один селектор и стрелки открывают любой документ комплекта, включая исключённые и файлы с ошибками чтения. Под селектором находятся страницы, масштаб и категории подсветки. Для исключений добавляется короткий статус. На вкладке «Документы» используется тот же просмотрщик. При сворачивании выбранного документа сохраняются его страница, масштаб и подсветка. Поддерживаемые адреса берутся из фактических данных источника. |
| Документы | «Все», «Прочитано», «Исключены» и «Ошибка чтения» при наличии таких файлов. Связи показаны названиями показателей или номерами статей. |
| Дополнительные проверки | После таблицы показаны имеющиеся исключения, состояние проблемных файлов и недостаточные подтверждения. Доступные источники открываются по ссылке. Исключённый дубль сам по себе не образует финансового расхождения. |
| Принятие и архив | Бухгалтер отмечает завершение работы с конкретной версией кнопкой «Принять проверку» внизу результата. Достоверность и результаты сверки сохраняются. В архиве отображается зелёный статус «Принят». Принятую версию можно открыть с её заключением и доказательствами. Эта отметка не является электронной подписью. |
| Комплект и версии | «Изменить комплект» позволяет добавить, заменить и исключить первичные документы, сохранив КФЗ и остальные файлы. Повторная демо-сверка создаёт новую непринятую версию. Предыдущая доступна во время обработки и после её окончания. Переключатель появляется рядом с вкладками при наличии второй версии и сохраняет её выбор при переходе между результатом и документами. |
| Демонстрационная обработка | Повторная сверка пересматривает доступные подтверждения и покрытие по сохранённому составу. Для новых файлов сохраняются названия и тип. Для них недоступны распознавание, просмотр оригинала и координаты. Демо использует существующие снимки источников из примеров и не сообщает об использовании кеша OCR. |

## Серверная интеграция MVP

- **Серверная очередь и история.** Передать один КФЗ и комплект первичных документов по существующему API. После подтверждения сервером очистить форму и отобразить стабильный идентификатор, время создания и состояние. Идентификатор и состояние должны восстанавливаться из API при повторном открытии. При повторе одной отправки использовать тот же `Idempotency-Key`, для следующего комплекта создавать новый. Подтверждение приёма — `202` с `run_id` и `Location`. Показывать передачу файлов отдельно. Для передачи использовать измеренные байты. Для прогресса обработки принимать текущую стадию, счётчики документов и время обновления от сервера. Процент показывать при наличии серверного значения или измеримого отношения обработанных документов к общему числу. При отсутствии сигнала сохранять название стадии и индикатор ожидания. Номер КФЗ использовать после подтверждённого извлечения. Состояния API `queued / processing / completed / completed_with_issues / failed` соответствуют «В очереди», «Обработка документов», «Готово», «Готово с замечаниями» и «Ошибка обработки». При наличии счётчиков показывать число обработанных документов. Проценты загрузки и отдельный этап «Сверка» доступны при наличии соответствующего сигнала. Для обоих успешных состояний показывать ссылку на доступный результат.
- Версионированный состав, идемпотентное принятие, архив, хранение исторических результатов и кеш извлечения входят в MVP интеграции. Предлагаемые операции, миграция и критерии приёмки описаны в [требованиях NRT-107](check-lifecycle-nrt107.md).

## Гипотезы

Гранулярные стадии и проценты после передачи файлов зависят от сигналов worker. Формат структурного адреса для листов и текстовых документов зависит от извлекателя и просмотрщика. Для принятия и версий названия операций и наборы полей подлежат согласованию с владельцем интеграции.

## Перенос через NRT-107

Цепочка **репозиторий Андрея → проверка изменений в main → адаптация в PR интегрированного DocCheck**. Обратный перенос визуальных компонентов требует отдельного согласования. [NRT-107](https://linear.app/andreiakimov/issue/NRT-107/sinhronizirovat-izmeneniya-interfejsa-andreya-s-doccheck).

1. Зафиксировать диапазон коммитов UX относительно последней интеграции. Сопоставить изменения с текущими `main` и PR №82–84 интегрированного приложения, чтобы переиспользовать существующую реализацию и тесты.
2. Сверить форматы, состояния очереди и доступность результата с действующим API. Для серверного списка использовать порядок `created_at` и `run_id` по убыванию. Сохранить сырые канонические статусы, точные суммы и `null`. Для формул отображать известные слагаемые и итог из результата. Не считать неполные или неоднозначные источники полным подтверждением.
3. Сохранить существующие источники и адреса доказательств, включая номер страницы и bbox или доступный структурный адрес. Формат данных проверять по [OpenAPI](https://github.com/VCyberPunk2077/doccheck/blob/main/contracts/doccheck-api.v0.openapi.yaml), UI адаптировать под источники, которые действительно доступны.
4. Указать диапазон, допущения, результаты UI и API-проверок в интеграционном PR. Техническая архитектура, сценарии К6, README и контракты интеграции ведутся в [VCyberPunk2077/doccheck](https://github.com/VCyberPunk2077/doccheck).
